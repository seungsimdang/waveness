# CodeRabbit Triage

## Overview

`coderabbit review --agent`로 구조화된 리뷰 findings를 받아, 프로젝트 컨벤션(`AGENTS.md`, `docs/agent-rules/project.md`)과 실제 버그 여부를 기준으로 채택/기각을 판정한다. 채택된 항목만 코드에 반영하고, 기각된 항목은 근거와 함께 보고한다.

## Workflow

1. **작업 트리 확인**: `git status`로 커밋되지 않은 변경이 있는지 확인한다. 리뷰 대상 변경이 없으면(clean) 사용자에게 리뷰할 대상(브랜치 diff 등)을 확인한다.
2. **coderabbit 실행**: `coderabbit review --agent`를 기본으로 실행한다.
   - 사용자가 범위를 지정하면 그에 맞는 옵션을 추가한다: 커밋된 변경만이면 `--committed`, base 브랜치 비교면 `--base <branch>`, 미추적 파일 포함이면 `--include-untracked`.
   - 인증 오류 등으로 명령이 실패하면 추측으로 진행하지 않고 오류 내용을 그대로 보고하고 중단한다.
3. **findings 파싱**: 출력에서 파일·라인·심각도·설명 단위로 지적 목록을 추출한다.
4. **채택/기각 판정**: 지적마다 아래 기준으로 판단한다.
   - **채택**: 실제 버그, 타입 안전성 위반, 보안 문제, 명백한 로직 오류
   - **기각**: `AGENTS.md`·`project.md` 컨벤션과 충돌하는 제안(예: `interface` 권장 → 이 프로젝트는 `type`만 허용이라 기각, `any` 완화 제안 등), 스타일 취향 차이, 요청 범위 밖 리팩토링 제안, 근거가 불충분하거나 현재 코드 의도를 오해한 지적
   - 판단이 애매하면 임의로 채택하지 않고 기각 쪽에 두고 사용자에게 별도로 확인을 구한다.
5. **수정 적용**: 채택된 항목만 `Edit`으로 반영한다. `Write`로 파일을 통째로 재작성하지 않는다. 파일별 기존 줄바꿈/포맷을 유지한다.
6. **재검증**: 수정이 하나라도 있었으면 `docs/agent-rules/project.md`의 타입 검사 명령을 실행해 타입 오류가 없는지 확인한다.
7. **결과 보고**: 채택/기각 전체 목록을 표로 정리해 응답에 직접 표시한다(별도 산출물 파일을 만들지 않는다 - 코드 diff 자체가 최종 산출물).

## 출력 형식

응답 본문에 아래 형태의 표를 포함한다.

| 상태 | 파일:라인 | 지적 요약 | 판정 근거 |
|---|---|---|---|
| 채택 | `src/foo.ts:42` | ... | ... |
| 기각 | `src/bar.ts:10` | ... | AGENTS.md 컨벤션(...)과 충돌 |

표 아래에 실제 반영한 파일 목록과 타입 검사 결과를 짧게 덧붙인다.

## 품질 기준

- 기각 판정에는 반드시 근거를 남긴다("애매해서 제외" 같은 모호한 사유 금지).
- 채택된 수정만 최소 범위로 반영한다. coderabbit 지적을 반영하는 김에 무관한 개선을 끼워 넣지 않는다.
- 타입체크가 실패하면 수정을 그대로 두지 않고 원인을 다시 확인해 고친다.

## 예외 상황

- `coderabbit` CLI 인증이 안 되어 있거나 실행 자체가 실패하면, 임의로 넘어가지 않고 오류를 보고한 뒤 중단한다.
- 지적이 여러 파일에 걸친 큰 리팩토링을 요구하면 자동으로 진행하지 않고 범위를 사용자에게 확인한다.
- 리뷰 결과 채택할 항목이 하나도 없으면 코드 수정 없이 판정표만 보고한다.
- 이 스킬은 `git commit`/`git push`를 실행하지 않는다. 커밋이 필요하면 `itd-commit` 스킬로 넘어가도록 안내한다.
